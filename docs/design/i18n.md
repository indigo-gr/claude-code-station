# 多言語対応（i18n）設計

> ccs v0.6.0 — ccs が人に向けて出す文を、日本語と英語で切り替える。後から言語を足せる形にする。機械で読む出力（`--json`・終了コード・語彙の語）は言語で変えない。

## 1. 範囲

| 対象 | 言語で切り替える | 備考 |
|---|:---:|---|
| 一覧（fzf）の見出し・枠のラベル・キーの案内 | ✅ | |
| プレビューの見出しと決まった文 | ✅ | `repos.yml` に利用者が書いた値（`label`・`description`・`custom`）は訳さない |
| 更新のお知らせ・警告・エラーの文（標準エラー） | ✅ | |
| `--help`・`ccs init` の問いかけと案内 | ✅ | |
| `doctor`（`--json` なし）の人向けの表 | ✅ | |
| `--json` の出力・終了コード・`status`・`reasons[].code`・`detail` | — | 言語で変えない（`machine-interface.md`）。`--json` の中の人向けの文の欄を足す時も、語は英語の決まった値にする |
| `ccs --version` の出力 | — | 機械で読む形（変えない） |
| README・CHANGELOG | 言語ごとのファイル | `README.md`・`CHANGELOG.md` は英語、`README.ja.md`・`CHANGELOG.ja.md` は日本語。互いに先頭で相手へのリンクを置く |
| `docs/design/` | — | 設計の資料は日本語のまま |

## 2. 言語の決め方

上から順に見て、最初に決まった物を使う。

| 順 | 見る物 | 値 |
|:---:|---|---|
| 1 | フラグ `--lang=<言語>` | `ja`・`en` |
| 2 | 環境変数 `CCS_LANG` | `ja`・`en` |
| 3 | `repos.yml` の `defaults.language` | `ja`・`en`・`auto`（`auto` と空・YAML の null は未指定） |
| 4 | OS の locale: `LC_ALL` → `LC_MESSAGES` → `LANG` の順で、最初の空でない物 | 先頭が `ja`（`ja_JP.UTF-8`・`ja`）なら `ja`。`C`・`POSIX` とほかは `en` |
| 5 | どれも無い | `en` |

- 1〜3 に知らない値（`fr` など）が来た時: 1 は引数の誤り（`usage`・2）。2 と 3 は 1 行の警告を出して、その段階を飛ばす（次の段階で決める）。`repos.yml` の誤りで一覧を開けなくしない
- macOS で locale の環境変数が空の時（GUI から起こされた時など）は、5 の `en` になる。日本語にしたい人は 2 か 3 で決める（`defaults.language: ja`）
- 決まった言語は、`bin/ccs`（bash）と TS の部品で同じ物を使う。bash が 1 回決めて、環境変数で部品に渡す（部品は自分で決め直さない）
- `defaults.language` は、起動の時に Node を呼ばないため bash が `repos.yml` を行で読んで取る（トップレベルの `defaults:` の 1 段下の `language:` だけ。1 行の形 `defaults: {language: ja}` は読めず、4 の段階に落ちる）
- `config set defaults.language <値>` で書ける。`config get` と `doctor --json` の `settings` に `language`（決まった言語）を足す（足すだけの変更）

## 3. 文の置き場

- 言語ごとに 1 つの文の表を持つ。キーは言語で共通。bash と TS の両方が同じ表を読む（表の形と読み方は engineer が決める。bash 3.2 で読めること）
- 表に無いキーは英語の文を使う（英語の表がキーの正）。英語の表にも無いキーは試験で落とす
- 文の中の差し込み（バージョン・パス・名前）は名前つきの差し込みにし、語順を言語ごとに変えられるようにする
- 差し込む値は今までどおり、出す前に制御文字と向きを変える文字を除く（訳した文の側では除かない＝表は信用する物）
- 言語を足す時は、表のファイルを 1 つ足し、2 の値の一覧に足すだけで済む形にする
- 表のファイルが無い置き方の時: 選んだ言語の表が無ければ英語の表を使う（警告なし）。英語の表も無ければ壊れた入れ方として、`bin/ccs` は表を使わずに書いた英語の 1 行（入れ直しを勧める）を標準エラーに出して 1 で終わる。キーの名前を画面に出さない。`--json` の口は文に頼らないので変えない

## 4. 試験で確かめる事（checker）

| 確かめる事 | 期待 |
|---|---|
| 2 の順の全部の組み合わせ（フラグ・環境変数・設定・locale・無し） | 表どおりの言語。知らない値は 2 の決まりどおり |
| 英語の表のキーが日本語の表に全部ある | 欠けがあれば落ちる（欠けを黙って英語にしない） |
| 差し込みの名前が言語の間で同じ | 片方にしか無い差し込みがあれば落ちる |
| `--json` の出力が言語で変わらない | `ja` と `en` で同じ JSON（時刻と、決まった言語を出す欄 `doctor` の `settings.language` を除く） |
| 一覧・お知らせ・エラー・`--help` が両方の言語で出る | 代表の文で見る |

## 5. 読む側への約束

- 機械で読む出力は言語で変わらない。読む側は標準エラーの文を読まない（`machine-interface.md` の 1.8 のまま）
- 足す物: `--lang` フラグ・`CCS_LANG`・`defaults.language`・`config get` と `doctor --json` の `settings.language`。どれも足すだけの変更
